This is the backend for a learning portal where teachers create mock tests and previous-year-question (PYQ) papers, students attempt them, and admins approve new accounts. It is a REST API built with Node.js, Express 5, and MySQL.
Overview:
The API supports three kinds of users: students, teachers, and admins. Anyone can sign up, but a student or teacher account must be approved by an admin before the user can log in. Passwords are hashed with bcrypt, and logging in returns a JSON Web Token that the frontend sends with later requests.
Teachers can create tests made of questions and options, add explanations, edit them, and publish them for students. Students can attempt published tests, and the server grades the answers. Tests with the subject GATE use negative marking, where each wrong answer subtracts one mark. Students can review their results and track their progress, and teachers can view how students performed on their tests and leave remarks.
Tech Stack:
The server uses Express for routing and mysql2 with its promise API and a connection pool for database access. Passwords are hashed with bcryptjs, tokens are issued and verified with jsonwebtoken, cors allows the frontend to call the API from another origin, dotenv loads environment variables, and nodemon restarts the server during development.
Project Structure:
The project is a flat set of files in the root folder. server.js is the entry point; it sets up middleware and mounts the routes. db.js creates the MySQL connection pool. authMiddleware.js verifies JWTs on protected routes. authRoutes.js handles signup and login, adminRoutes.js handles the admin dashboard and account approval, and mockTestRoutes.js contains everything related to tests, attempts, results, and progress. The .env file holds your configuration and should never be committed.
Database:
The code expects six tables. The usersinfo table stores each user's id, name, email (which should be unique), hashed password, role, registration ID, approval status, and creation time. The mock_tests table stores each test's id, the teacher's user id, the test name, description, subject, exam type (either PYQ or MOCK), and a can_attempt flag that marks it as published. The questions table stores the question text and explanation for each test, and the options table stores each question's answer choices along with an is_correct flag. The user_answers table records every answer a student gives, and the user_test_attempts table records the final score, total questions, time taken, submission time, and any teacher remark for each attempt. These columns were inferred from the queries in the code, so adjust the types to match your own setup.
Authentication:
Protected routes expect the token in the Authorization header in the form Bearer <token>. You get the token from the login endpoint, and it expires after 15 days. The three roles are student, teacher, and admin. Admins can always log in, while students and teachers can only log in once their status is Approved.
API Reference:
The base URL is http://localhost:5000.
Auth routes (/api/auth)
POST /api/auth/signup registers a new user.
It returns 201 on success, 400 if a field is missing, and 409 if the email is already registered.
POST /api/auth/login logs a user in. It returns 400 for missing fields, 401 for wrong credentials, and 404 with a "Contact Administrator" message if the account has not been approved.
Admin routes (/api/admin)
All admin routes require a token. GET /api/admin/stats returns the number of students and teachers. GET /api/admin/users-by-role?role=student&search=abc lists users of the given role, newest first, and the optional search parameter filters by name or registration ID. PUT /api/admin/update-status/:id changes a user's status, with a body such as { "status": "Approved" }. This is how an admin approves new accounts.
Teacher routes (/api/test)
POST /api/test/mock-tests/full creates a test together with all its questions and options in a single database transaction, so either everything is saved or nothing is. It requires a token and takes the teacher's id from it.
GET /api/test/mock-tests returns the logged-in teacher's tests along with how many questions each has. GET /api/test/mock-test/full/:id loads a complete test for editing, and PUT /api/test/mock-test/full/:id replaces its details and questions. PUT /api/test/mock-tests/:id/can-attempt publishes a test so students can see it, and DELETE /api/test/mock-test/:id deletes a test with its questions and options. There are also older, piecemeal endpoints: POST /api/test/mock-tests creates a test without questions, POST /api/test/questions adds a single question, and POST /api/test/questions/bulk adds several at once. The /full endpoint makes these mostly unnecessary.
For reviewing students, GET /api/test/student-analysis returns every attempt made on the teacher's tests, with percentage and a pass or fail status, and PUT /api/test/update-remark saves a remark on an attempt using a body of { "user_id": 12, "mock_test_id": 3, "remark": "Good effort" }. Both require a token.
Right now only some of these routes check for a token, and none check the user's role. See the Known Issues section below.
Student routes (/api/test)
GET /api/test/mock-tests/:subject lists the published tests for a subject, grouped into PYQ and MOCK, and includes the student's score when they have already attempted a test. GET /api/test/mock-tests/:mockTestId/questions returns a test's questions and options without revealing the correct answers.
POST /api/test/mock-tests/:mockTestId/submit submits a student's answers and returns the score.
Each correct answer scores one mark, skipped questions score nothing, and wrong answers subtract one mark only for GATE tests.
After submitting, GET /api/test/mock-tests/:mockTestId/results returns every question with its options, which option is correct, the explanation, and what the student chose. GET /api/test/mock-tests/:mockTestId/attempt returns just the score, total, and time taken. GET /api/test/student/progress returns the student's full attempt history with percentage and a pass or fail status, and GET /api/test/student/progress/summary returns how many tests are available compared with how many the student has attempted. All of these require a token.
